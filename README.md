# Home Food · 我的家常菜助手

一个用自然语言操作的做饭 Skill。你只需提供“菜名 + 基础食材 + 参考视频链接”，助手就会读取视频，整理成材料和最简步骤。平时只推荐你亲自做过、确认好吃、并补充进菜谱库的菜。

**菜谱和来源由你提供，助手负责整理和推荐。** 可以导入你指定的视频，不自行搜集新菜，不擅自添加食材、调味、用量或制作步骤。

## 平时怎么用

### 1. 用三行录入一道菜

按 [简略录入模板](templates/intake.md) 提供这三项即可，例如：

```text
菜名：肥牛滑蛋
基础食材：肥牛、鸡蛋、洋葱
参考视频：https://xhslink.cn/o/8dhOKyFwkhV
```

基础食材写主料和想记下的辅料就行。盐、油、酱油等常备调味料可以不写，也不用手写用量和完整制作过程。助手会从你指定的视频中提取明确用到的其他材料、调味料及步骤，不会先要求你补齐一份完整食谱。

如果已经做过并确认好吃，可以再补一句“这道菜我做过，好吃”。尚未验证的菜先作为草稿保存，不进入推荐范围。

### 2. 自动整理成做饭笔记

助手会读取你提供的参考视频，提取材料、用量和制作过程。删掉寒暄、广告和重复解释，保留时间、火力、工具、关键顺序等做菜需要的信息，像自己的做饭笔记那样直接写操作。

常备调味料不必在录入时列全，但整理后的菜谱会记录视频明确用到的调味料。有明确用量就保留，没有用量就只写材料名。没有依据的材料或步骤不会自行添加，菜谱中不写缺项清单、作者或提取过程。

参考视频分享链接保留在菜谱的文件信息字段中，随菜谱同步 GitHub，方便回看；正文仍只有材料和最简步骤。

其他录入方式也继续支持：

> 把这个做菜视频转成我的菜谱模板，列出材料和最简制作步骤：[视频链接]

> 下面是视频文案，帮我整理成材料和最简步骤：……

也可以像“苹果清炖牛肋条”一样，直接口述材料和做法；已经说清楚的信息不用再填一遍。

**导入后默认是待验证草稿，不参与日常推荐。** 等你做过并确认“好吃”，再将其改为验证成功；如果导入时已明确说这份做法亲自实验成功，可以直接标为成功。

若链接无法读取，会先保存你给的菜名、基础食材和参考链接，再请你提供对应文案或本地视频；不会只凭标题生成做法。尚未取得制作步骤的条目不能当作可直接执行的菜谱推荐。

同名菜已有成功版本时，新的视频做法另存为待验证版本，避免覆盖你已经验证的配方。只有你明确说明是在补充或修正原菜谱时，才更新原文件。

### 3. 让助手推荐

可以直接说：

- “今天做什么？从我的菜谱里推荐一道。”
- “我有牛肋条和苹果，能做什么？还缺哪些材料？”
- “给我推荐一道用电饭煲做的菜。”
- “今天只有 30 分钟，有没有适合的菜？”

助手会读取已验证的菜谱，根据你本次提供的食材、时间或工具筛选。如果没有符合条件的菜，会说明原因；只有一道符合，就只推荐这一道。

### 4. 看食材和最简步骤

每次推荐提供：

1. **菜名**。
2. **原材料**：必需材料、可选材料；有需要时按酱汁等用途分组。
3. **最简步骤**：按制作顺序列出，保留你记录的时间、工具和关键操作。

提供现有食材或询问备料时，可以在菜谱外列出还需准备的必需材料。没说过的份量、调味或时间直接省略；可选材料保持可选。

### 5. 持续完善

做完后可以补充水量、份量、步骤或自己的经验，例如：“这道菜补充一下，实际水量是……”

助手会更新原菜谱；只有你明确提供的修正才会成为新的记录。对于视频导入的草稿，可以说“这道菜我做过了，好吃”，将实际做法补充进去并开启推荐。验证状态只保留在文件信息字段中，菜谱正文保持简洁。

本项目已约定：每次新增或修改菜谱后，检查并提交、同步到现有 GitHub 仓库，无需每次另说。同步失败时会保留本地文件并说明结果。

## 作为 Skill 使用

项目根目录就是 `home-food` Skill，入口为 [SKILL.md](SKILL.md)。它需要由支持 Skill 的 AI 助手读取，不是一个独立的网页或应用。

在这个项目中，直接向助手提出做饭需求即可；[AGENTS.md](AGENTS.md) 会指向 Skill 的规则。

也可以将仓库安装到 Codex 的用户 Skill 目录（目标文件夹尚不存在时）：

```bash
git clone https://github.com/SucRunBug/home-food.git ~/.codex/skills/home-food
```

重新打开会话后，可以明确调用：

```text
使用 $home-food，从我验证过的菜谱里推荐一道今晚做的菜，列出原材料和最简步骤。
```

安装副本和项目原目录是不同文件夹。以实际调用的 Skill 文件夹中的 `recipes/` 为准，补充菜谱时修改该文件夹。

### 换一台电脑看视频

拉取最新版完整仓库，并在 Codex 中打开这个项目，或安装完整 Skill 文件夹。不要只复制 `SKILL.md`；视频读取工具和说明也需要一起带过去。新电脑需要 Python 3.9 或更新版本、FFmpeg 和 FFprobe，以及能实际查看本地图片的 Codex 工具；音频讲解还需要可用的转写能力。

可以直接对 Codex 说：

> 使用 home-food，先按视频读取说明检查当前电脑，再读取这个视频并整理菜谱：[视频链接]

之前「肥牛滑蛋」读取成功的路径已做成配套工具：展开小红书分享链接 → 读取手机分享页 → 取得当前视频地址 → 下载 → 抽帧并查看字幕和操作。那次依靠画面与嵌入字幕，没有使用语音转写。换电脑时会重新取得媒体地址，不能复用旧电脑上可能过期的临时地址。

具体步骤、环境检查和失败处理见 [视频读取与换电脑复用说明](references/video-reading.md)。小红书下载工具只处理用户给出的该平台链接；通用抽帧工具可以处理已经取得的其他平台视频和本地视频。登录要求、视频删除或当前工具能力不足时，会说明实际限制。

## 文件结构

```text
home-food/
├── README.md               项目说明
├── SKILL.md                推荐、视频导入、录入、修改的规则
├── AGENTS.md               在本项目中使用 Skill 的入口提示
├── agents/openai.yaml      Skill 在 Codex 中的显示信息
├── recipes/                你提供的菜谱，唯一菜谱来源
│   ├── apple-beef-ribs.md
│   ├── beef-scrambled-eggs.md
│   ├── celery-stir-fried-beef.md
│   └── garlic-beef-mushrooms.md
├── references/
│   ├── video-import.md     视频导入和菜谱提取流程
│   └── video-reading.md    成功路径、换电脑检查和故障处理
├── scripts/
│   ├── fetch_xhs_video.py  小红书手机分享页视频下载
│   └── prepare_video.py    视频检查、完整画面、联系表和音频
├── tests/test_video_reader.py  视频读取工具的离线检查
└── templates/
    ├── intake.md           用户简略录入模板：菜名、基础食材、参考视频
    └── recipe.md           助手整理后的菜谱保存格式，不参与推荐
```

每道菜单独一个 Markdown 文件，包含 `name`、`verified`，以及可选的 `reference_video` 信息字段；正文只有菜名、原材料和制作步骤。只有 `verified: true` 且由你确认实验成功的菜谱可以推荐。

日常录入用 [简略录入模板](templates/intake.md)，不用手写完整菜谱。[菜谱保存模板](templates/recipe.md) 由助手整理填写；模板默认 `verified: false`，实际验证成功后再改为 `true`。愿意自己整理时，也可以手动编辑菜谱文件。

视频导入流程见 [视频导入说明](references/video-import.md)。参考分享链接保留在菜谱中；提取依据、原文、视频、音频和转写稿在本地 `sources/` 文件夹保存，已被 Git 忽略，不上传公开仓库。

公开仓库发布整理后的菜谱和项目说明、规则。
