# Home Food · 我的家常菜助手

一个用自然语言操作的做饭 Skill。它可以把你提供的做菜视频链接或视频文案转成“材料 + 最简步骤”；平时只推荐你亲自做过、确认好吃、并补充进菜谱库的菜。

**菜谱和来源由你提供，助手负责整理和推荐。** 可以导入你指定的视频，不自行搜集新菜，不擅自添加食材、调味、用量或制作步骤。

## 平时怎么用

### 1. 补充一道成功的菜

直接告诉助手菜名、原材料和做法，说明这道菜已经实验成功。可以一次说完，也可以分几条消息补充：

> 这道菜我做过，好吃，帮我录入：苹果清炖牛肋条。材料有苹果、牛肋条、姜、洋葱，大葱和香菜可选……

助手会整理成一份菜谱文件。缺少的信息标为“待补充”，不会凭经验填空。只是想尝试、尚未验证的菜可以作为草稿保存，但不会进入推荐范围。

### 2. 从视频链接或文案导入

把视频链接或对应文案发给助手即可，例如：

> 把这个做菜视频转成我的菜谱模板，列出材料和最简制作步骤：[视频链接]

> 下面是视频文案，帮我整理成材料和最简步骤：……

助手会先尝试读取链接对应的实际字幕、文案或视频内容，再提取材料、用量和制作过程。删掉寒暄、广告和重复解释，保留时间、火力、工具、关键顺序等做菜需要的信息。

**导入后默认是待验证草稿，不参与日常推荐。** 等你做过并确认“好吃”，再将其改为验证成功；如果导入时已明确说这份做法亲自实验成功，可以直接标为成功。

来源里没有的用量或步骤仍标为待补充。若链接无法读取，会请你提供对应文案或本地视频；不会只凭标题生成做法，也不保证每个平台的链接都能直接读取。

同名菜已有成功版本时，新的视频做法另存为待验证版本，避免覆盖你已经验证的配方。只有你明确说明是在补充或修正原菜谱时，才更新原文件。

### 3. 让助手推荐

可以直接说：

- “今天做什么？从我的菜谱里推荐一道。”
- “我有牛肋条和苹果，能做什么？还缺哪些材料？”
- “给我推荐一道用电饭煲做的菜。”
- “今天只有 30 分钟，有没有适合的菜？”

助手会读取已验证的菜谱，根据你本次提供的食材、时间或工具筛选。如果没有符合条件的菜，会说明原因；只有一道符合，就只推荐这一道。

### 4. 看食材和最简步骤

每次推荐提供：

1. **菜名和推荐理由**：理由来自菜谱和你本次的需求。
2. **原材料**：必需材料、可选材料；提供现有食材时，列出缺少的必需材料。
3. **最简步骤**：按制作顺序列出，保留你记录的时间、工具和关键操作。
4. **待补充信息**：只在菜谱有缺项时显示。

份量、调味或时间没有记录，就明确说没有记录。可选材料不会变成必需材料，也不会给你安排库中没有的配菜。

### 5. 持续完善

做完后可以补充水量、份量、步骤或自己的经验，例如：“这道菜补充一下，实际水量是……”

助手会更新原菜谱；只有你明确提供的修正才会成为新的记录。对于视频导入的草稿，可以说“这道菜我做过了，好吃”，将实际做法补充进去并开启推荐。菜谱保存在本地文件中，修改不会自动上传 GitHub，需要你提出同步要求。

## 作为 Skill 使用

项目根目录就是 `home-food` Skill，入口为 [SKILL.md](SKILL.md)。它需要由支持 Skill 的 AI 助手读取，不是一个独立的网页或应用。

在这个项目中，直接向助手提出做饭需求即可；[AGENTS.md](AGENTS.md) 会指向 Skill 的规则。

也可以将仓库安装到 Codex 的用户 Skill 目录（目标文件夹尚不存在时）：

```bash
git clone https://github.com/SucRunBug/home-food.git ~/.codex/skills/home-food
```

重新打开会话后，可以明确调用：

```text
使用 $home-food，从我验证过的菜谱里推荐一道今晚做的菜，列出原材料和最简步骤。
```

安装副本和项目原目录是不同文件夹。以实际调用的 Skill 文件夹中的 `recipes/` 为准，补充菜谱时修改该文件夹。

## 文件结构

```text
home-food/
├── README.md               项目说明
├── SKILL.md                推荐、视频导入、录入、修改的规则
├── AGENTS.md               在本项目中使用 Skill 的入口提示
├── agents/openai.yaml      Skill 在 Codex 中的显示信息
├── recipes/                你提供的菜谱，唯一菜谱来源
│   └── apple-beef-ribs.md
├── references/video-import.md  视频读取和菜谱提取流程
└── templates/recipe.md      新菜谱模板，不参与推荐
```

每道菜单独一个 Markdown 文件，包含 `name` 和 `verified` 两个信息字段，以及原材料、制作步骤、待补充信息、来源和备注。只有 `verified: true` 且由你确认实验成功的菜谱可以推荐。

你可以让助手录入，也可以复制 [菜谱模板](templates/recipe.md) 后手动填写。模板默认 `verified: false`；实际验证成功后再改为 `true`。

视频导入流程见 [视频导入说明](references/video-import.md)。需要保存原文、视频、音频或转写稿时，会创建本地 `sources/` 文件夹；它已被 Git 忽略，不上传公开仓库。

公开仓库中的文件对所有人可见，因此只发布整理后的菜谱、来源页面链接和与制作有关的经验。
