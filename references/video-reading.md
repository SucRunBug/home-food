# 视频读取：换电脑也能复用的路径

供执行 Skill 的助手使用。先取得目标视频，再实际查看画面或转写音频，最后按 [视频导入规则](video-import.md) 整理菜谱。下载成功不等于已经读懂视频。

## 之前如何读到「肥牛滑蛋」

用户给出的链接是 `https://xhslink.cn/o/8dhOKyFwkhV`。当时普通网页读取没有取得内容，桌面页面跳转到登录页，浏览器工具也超时。实际成功的是以下路径：

1. 展开分享短链接，从登录跳转地址的 `redirectPath` 取回原笔记地址，保留分享参数。
2. 将原笔记地址改用 HTTPS，以 iPhone Safari 的 User-Agent 请求手机分享页。
3. 从页面内的 `window.__SETUP_SERVER_STATE__` 解码 JSON，确认目标笔记，再取 `LAUNCHER_SSR_STORE_PAGE_DATA.noteData.video.media.stream.h264[0].masterUrl`。
4. 使用浏览器 User-Agent 和小红书 Referer 下载当前页面提供的 MP4。
5. 用 FFmpeg 抽出完整画面和联系表，实际查看嵌入字幕与操作；用单帧确认鸡蛋数量、酱汁用量等细节。

这次记录依靠画面和嵌入字幕，没有运行语音转写，也没有依赖浏览器登录。目标笔记 ID 为 `67f4e33e000000001b025337`，视频约 42.18 秒、720 × 1280。页面结构可能变化；这些值只用于复现核对，不是其他视频的固定参数。

关键经验：先区分网页工具失败和视频本身不可访问；换用同一笔记的手机分享页可能成功。媒体地址可能过期，每次应重新从分享页取得，不能把之前电脑上的临时地址复制过来长期使用。

## 先检查当前电脑

1. 定位本次实际调用的 Skill 根目录，确认包含 `scripts/`、`references/` 和 `recipes/`。换电脑时拉取最新版完整仓库；只复制 `SKILL.md` 无法获得配套工具。
2. 找到可用的 Python 3.9 或更新版本。以下命令从 Skill 根目录执行；实际使用绝对路径时，根据当前电脑解析，不能复制旧电脑的路径。

   ```bash
   python3 scripts/fetch_xhs_video.py --check
   ```

   Windows 可将 `python3` 换成可用的 `py -3` 或 `python`。脚本只使用 Python 标准库，不依赖额外 Python 包。
3. 核对输出中的 `ffmpeg` 和 `ffprobe`。若为 `false`，先找当前电脑已有的可执行文件；后续可用 `--ffmpeg` 和 `--ffprobe` 指定路径。确实缺少时，按当前环境的安装权限准备这两个工具。Python 环境检查本身不测试联网，也不证明 Codex 可以查看图片。
4. 确认当前 Codex 能运行本地命令、访问目标网站，并有实际查看本地图片的工具。抽帧脚本只生成图片；它不会识别字幕，也不会自动生成菜谱。若只有文件操作能力，必须另找可用的图片读取或转写能力，不能声称看过视频。

不要绑定旧电脑的代理端口、浏览器用户目录、Cookie 文件或工具安装路径。脚本遵循当前进程的标准代理设置；需要联网权限时，走当前环境的正常授权流程。

## 小红书：优先执行可复现路径

收到小红书分享链接且需要查看视频时，先运行配套脚本；不要因普通网页工具打不开就直接让用户手写完整做法。

```bash
python3 scripts/fetch_xhs_video.py 'https://xhslink.cn/o/8dhOKyFwkhV' --output sources/beef-egg
python3 scripts/prepare_video.py sources/beef-egg/video.mp4 --interval 1
```

把链接和输出目录换成本次的目标。脚本会尝试公开手机页面，核对笔记 ID，按 H.264 优先选择同一视频的媒体地址，并检查下载响应确实是 MP4。不会执行网页里的 JavaScript。其他平台不使用这个下载脚本。

第一步在本地保存页面、笔记数据、`source.json` 和 `video.mp4`；第二步检查媒体轨和时长，生成 `analysis/frames/`、`analysis/sheets/`、`analysis/media.json`。原始页面可能含临时访问参数，这些文件都只放在被 Git 忽略的 `sources/`，不上传。

### 实际读画面

1. 用当前 Codex 的图片查看工具逐张打开生成的联系表，确认视频确实在做目标菜。不要只列出文件名就宣称读取成功。
2. 短视频默认每秒一帧，超过两分钟默认每三秒一帧。联系表便于定位；材料数量、字幕、小字和关键动作要打开完整单帧核对。默认不裁切画面，避免遗漏上下方字幕。
3. 一闪而过的字幕或动作可能落在采样间隔之间。缩短间隔，或根据画面位置提取准确时间，例如：

   ```bash
   python3 scripts/prepare_video.py sources/beef-egg/video.mp4 --interval 0.5 --at 6 15 24 32
   ```

   `--at` 单位是秒，必须在实际时长范围内。联系表格子与普通帧编号仅帮助定位，精确核对使用 `--at` 生成的单帧。
4. 检查是否覆盖备料、调味、关键操作和收尾；画面不能说明的内容不要补写。局部可读就记录局部范围，不能把稀疏抽帧或简介当成完整做法。

### 需要听讲解时

嵌入字幕不能覆盖做法，而音频可能提供信息时，提取音频：

```bash
python3 scripts/prepare_video.py sources/beef-egg/video.mp4 --audio
```

输出 `analysis/audio.wav`。检查本机可用加速后端后，再用实际可用的转写工具：Apple Silicon 优先 MLX / Metal / CoreML，NVIDIA 优先 CUDA；加速不可用、安装成本明显过高或任务很短时才回退 CPU。保留原始稿 `transcript-raw.txt` 和修正明显错字的 `transcript-clean.txt`，不把仅提取音频称为转写完成。数量和动作仍需结合实际画面。

## 失败时按层处理

| 现象 | 下一步 |
| --- | --- |
| 没有 Python 或媒体工具 | 找当前机器的可用路径，或按权限安装；不要默认为链接失效。 |
| 网络超时、连接或代理错误 | 检查当前终端的联网权限、代理和连接；与网页登录问题分开处理。 |
| HTTPS 证书验证失败 | 检查当前 Python 的证书配置及代理证书；保持证书验证开启。 |
| 没有匹配的笔记数据 | 用可用浏览器打开同一分享链接，确认笔记、公开手机页面和当前结构。需要登录时使用用户已有的授权访问，不绕过限制。 |
| 媒体请求返回 403、过期或非 MP4 | 重新读取分享页，取得新媒体地址；核对当前 User-Agent、Referer。不能把错误页面当作视频。 |
| 脚本下载失败，但当前浏览器可播放 | 通过环境允许的浏览器网络能力取得该视频实际请求的媒体地址，再使用通用抽帧脚本。只处理用户指定的视频。 |
| 已生成图片但看不清或缺讲解 | 打开完整单帧、缩短间隔、精确定位，必要时提取音频转写。 |
| 当前 Codex 没有图片读取或转写能力 | 明确指出缺少的能力；保存用户输入，在菜谱外请求对应文案或本地素材。不能凭菜名生成做法。 |

脚本单次只尝试少量页面和媒体候选。遇到权限、删除、登录要求或持续的结构变化时，不反复重试同一路径。可用路径都无法读取后，保留菜名、基础食材和参考链接，按视频导入规则说明实际限制。

## 其他平台与本地视频

从用户指定页面、关联字幕或可用浏览器获取实际内容。需要下载抖音时，按 [视频导入说明](video-import.md) 的浏览器媒体请求路径处理。已经取得本地视频后，都可以用 `prepare_video.py` 生成画面和音频；它不负责其他平台的链接解析。

若页面已有完整且能对应目标视频的文字做法，可以直接整理文本；需要确认视觉参数时仍要看画面。标题、搜索摘要、评论和其他菜谱不能替代目标视频。

## 读取完成的依据

在本地 `sources/<菜谱标识>/extracted-notes.md` 记录：分享链接、匹配到的笔记 ID / 标题、媒体时长和轨道、实际查看的图片或实际转写的文件、关键材料与操作对应的画面位置、读取范围。只写实际完成的操作。

最终菜谱仍只有菜名、材料和最简步骤；参考分享链接保留在 `reference_video`，验证状态保留在 `verified`。成功下载或完整提取视频都不能代替用户亲自验证好吃。
